# HHMS Deployment Guide — CloudPanel VPS
**Target:** https://nodescare.nodestech.cloud

CloudPanel manages Nginx, PHP-FPM, MySQL, and SSL directly.
**Do NOT use Docker** on CloudPanel — it handles everything natively.

---

## Prerequisites on your VPS

SSH into your server as root and verify:

```bash
php8.2 --version        # Must be 8.2+
composer --version      # Must be 2.x
mysql --version         # Must be 8.0+
redis-cli ping          # Must return PONG
node --version          # Must be 18+
npm --version
```

Install Redis if not present:
```bash
apt-get install -y redis-server
systemctl enable redis-server
systemctl start redis-server
```

Install Supervisor (for queue workers):
```bash
apt-get install -y supervisor
systemctl enable supervisor
systemctl start supervisor
```

## Step 1 — Create the site in CloudPanel

1. Log in to CloudPanel at `https://your-vps-ip:8443`
2. Click **+ Add Site** → **Create a PHP Site**
3. Fill in:
   - **Domain Name:** `nodescare.nodestech.cloud`
   - **PHP Version:** `8.2`
   - **vHost Template:** `Laravel 12` (or Generic PHP)
   - **Site User:** `hhms` (or any username)
   - **Site User Password:** (strong password)
4. Click **Create**

CloudPanel will automatically:
- Create an Nginx vhost
- Set document root to `/home/hhms/htdocs/nodescare.nodestech.cloud/public`
- Issue a free Let's Encrypt SSL certificate

---

## Step 2 — Upload the backend files

### Option A — Git (recommended)

SSH in as the site user:
```bash
ssh hhms@your-vps-ip
cd /home/hhms/htdocs/
rm -rf nodescare.nodestech.cloud
git clone https://github.com/your-org/hhms.git nodescare.nodestech.cloud
cd nodescare.nodestech.cloud
```

### Option B — SFTP / File Manager

Upload the entire `backend/` folder contents to:
```
/home/hhms/htdocs/nodescare.nodestech.cloud/
```

The folder structure on the server should be:
```
/home/hhms/htdocs/nodescare.nodestech.cloud/
├── app/
├── bootstrap/
├── config/
├── database/
├── public/          ← CloudPanel document root points here
├── resources/
├── routes/
├── storage/
├── vendor/          ← generated by composer install
├── .env             ← you create this
└── artisan
```

> **Important:** Upload the contents of your local `backend/` folder,
> NOT the `backend/` folder itself.

## Step 3 — Create the MySQL database

In CloudPanel:
1. Go to **Databases** → **Add Database**
2. Fill in:
   - **Database Name:** `hhms_central`
   - **Database User:** `hhms_user`
   - **Database Password:** (strong password — save it)
3. Click **Create**

## Step 4 — Configure the .env file

SSH into the server:
```bash
ssh hhms@your-vps-ip
cd /home/hhms/htdocs/nodescare.nodestech.cloud
cp .env.example .env
nano .env
```

Set these values:

```env
APP_NAME="Hospital Health Management System"
APP_ENV=production
APP_KEY=                          # generated in Step 5
APP_DEBUG=false
APP_URL=https://nodescare.nodestech.cloud

LOG_CHANNEL=stack
LOG_LEVEL=error

# Database (from Step 3)
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=hhms_central
DB_USERNAME=hhms_user
DB_PASSWORD=your_db_password_here

# Tenant DB uses same MySQL server
TENANT_DB_HOST=127.0.0.1
TENANT_DB_PORT=3306
TENANT_DB_USERNAME=hhms_user
TENANT_DB_PASSWORD=your_db_password_here

# Cache / Queue / Session — use Redis
BROADCAST_DRIVER=pusher
CACHE_DRIVER=redis
FILESYSTEM_DISK=s3
QUEUE_CONNECTION=redis
SESSION_DRIVER=redis
SESSION_LIFETIME=120

# Redis (local, no password by default on CloudPanel)
REDIS_HOST=127.0.0.1
REDIS_PASSWORD=null
REDIS_PORT=6379

# Mail — use your SMTP provider
MAIL_MAILER=smtp
MAIL_HOST=smtp.gmail.com          # or your provider
MAIL_PORT=587
MAIL_USERNAME=your@email.com
MAIL_PASSWORD=your_app_password
MAIL_ENCRYPTION=tls
MAIL_FROM_ADDRESS=noreply@nodescare.nodestech.cloud
MAIL_FROM_NAME="HHMS"

# Cloudflare R2 (file storage)
AWS_ACCESS_KEY_ID=your_r2_access_key
AWS_SECRET_ACCESS_KEY=your_r2_secret_key
AWS_DEFAULT_REGION=auto
AWS_BUCKET=hhms-storage
AWS_ENDPOINT=https://your-account-id.r2.cloudflarestorage.com
AWS_USE_PATH_STYLE_ENDPOINT=false

# Soketi WebSocket — running locally on port 6001
PUSHER_APP_ID=hhms-app
PUSHER_APP_KEY=hhms-key-change-me
PUSHER_APP_SECRET=hhms-secret-change-me
PUSHER_HOST=127.0.0.1
PUSHER_PORT=6001
PUSHER_SCHEME=http
PUSHER_APP_CLUSTER=mt1

VITE_PUSHER_APP_KEY="${PUSHER_APP_KEY}"
VITE_PUSHER_HOST="${PUSHER_HOST}"
VITE_PUSHER_PORT="${PUSHER_PORT}"
VITE_PUSHER_SCHEME="${PUSHER_SCHEME}"
VITE_PUSHER_APP_CLUSTER="${PUSHER_APP_CLUSTER}"

# JWT
JWT_SECRET=                       # generated in Step 5
JWT_TTL=60
JWT_REFRESH_TTL=10080

# Tenancy
TENANCY_DATABASE_AUTO_DELETE=false
TENANCY_DATABASE_AUTO_DELETE_USER=false

# Super Admin seed credentials
SUPER_ADMIN_NAME="System Administrator"
SUPER_ADMIN_EMAIL=admin@nodescare.nodestech.cloud
SUPER_ADMIN_PASSWORD=YourStrongPassword123!

# SMS (set to null until you configure a provider)
SMS_DRIVER=null

# Firebase (optional — for push notifications)
FIREBASE_CREDENTIALS=
```

Save and exit (`Ctrl+X`, `Y`, `Enter`).

## Step 8 — Install and run Soketi (WebSocket server)

Soketi needs Node.js. Install it as a background service:

```bash
# Install Soketi globally
npm install -g @soketi/soketi

# Test it works
soketi --version
```

Create a Supervisor config for Soketi:
```bash
nano /etc/supervisor/conf.d/hhms-soketi.conf
```

Paste:
```ini
[program:hhms-soketi]
command=soketi start --config=/home/hhms/soketi.json
directory=/home/hhms
user=hhms
autostart=true
autorestart=true
redirect_stderr=true
stdout_logfile=/var/log/hhms-soketi.log
```

Create the Soketi config file:
```bash
nano /home/hhms/soketi.json
```

Paste (use the same values as your .env):
```json
{
  "debug": false,
  "port": 6001,
  "appManager.driver": "array",
  "appManager.array.apps": [
    {
      "id": "hhms-app",
      "key": "hhms-key-change-me",
      "secret": "hhms-secret-change-me",
      "maxConnections": 1000,
      "enableClientMessages": false,
      "enabled": true
    }
  ],
  "database.driver": "redis",
  "replicaCount": 1
}
```

Start Soketi:
```bash
supervisorctl reread
supervisorctl update
supervisorctl start hhms-soketi
supervisorctl status hhms-soketi
```

## Step 9 — Set up queue workers

Create a Supervisor config for Laravel queue workers:
```bash
nano /etc/supervisor/conf.d/hhms-queue.conf
```

Paste:
```ini
[program:hhms-queue-default]
command=php8.2 /home/hhms/htdocs/nodescare.nodestech.cloud/artisan queue:work redis --sleep=3 --tries=3 --max-time=3600
directory=/home/hhms/htdocs/nodescare.nodestech.cloud
user=hhms
numprocs=2
autostart=true
autorestart=true
redirect_stderr=true
stdout_logfile=/var/log/hhms-queue.log

[program:hhms-queue-high]
command=php8.2 /home/hhms/htdocs/nodescare.nodestech.cloud/artisan queue:work redis --queue=high --sleep=3 --tries=3 --max-time=3600
directory=/home/hhms/htdocs/nodescare.nodestech.cloud
user=hhms
numprocs=1
autostart=true
autorestart=true
redirect_stderr=true
stdout_logfile=/var/log/hhms-queue-high.log
```

Start queue workers:
```bash
supervisorctl reread
supervisorctl update
supervisorctl start hhms-queue-default:*
supervisorctl start hhms-queue-high:*
supervisorctl status
```

## Step 11 — Configure CloudPanel Nginx vhost

In CloudPanel, go to your site → **Vhost** and verify the document root is set to the `public` folder. It should look like:

```nginx
root /home/hhms/htdocs/nodescare.nodestech.cloud/public;
```

If it's pointing to the root instead of `/public`, click **Settings** → change **Document Root** to `public`.

Also add these Nginx directives in the vhost for Laravel:
```nginx
location / {
    try_files $uri $uri/ /index.php?$query_string;
}
```

CloudPanel's Laravel template already includes this — just verify it's there.

## Troubleshooting

### 500 error on the site
```bash
tail -50 /home/hhms/htdocs/nodescare.nodestech.cloud/storage/logs/laravel.log
```

### Permission denied errors
```bash
chmod -R 775 storage bootstrap/cache
chown -R hhms:hhms /home/hhms/htdocs/nodescare.nodestech.cloud
```

### Queue jobs not processing
```bash
supervisorctl restart hhms-queue-default:*
supervisorctl tail hhms-queue-default
```

### Tenant database not created
When you create a hospital via the Super Admin panel, the `TenantProvisioningJob` runs and creates the tenant database automatically. Make sure queue workers are running (Step 9).

### WebSocket not connecting
```bash
supervisorctl status hhms-soketi
# Check port 6001 is open
netstat -tlnp | grep 6001
# Open it in your VPS firewall if needed
ufw allow 6001/tcp
```

### Clear all caches after code update
```bash
cd /home/hhms/htdocs/nodescare.nodestech.cloud
php8.2 artisan cache:clear
php8.2 artisan config:cache
php8.2 artisan route:cache
php8.2 artisan view:cache
supervisorctl restart hhms-queue-default:*
supervisorctl restart hhms-queue-high:*
```
